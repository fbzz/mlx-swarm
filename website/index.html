Product tagline

Your frontier agent keeps diagnosis and design. The local model receives exact, bounded jobs.

Frontier models should not rewrite every file

Sending each implementation step through a frontier model is expensive. Asking one small model to solve a whole repository task is usually unreliable.

MLX Swarm splits the jobs. The strong model owns diagnosis and the graph. The local model executes small, explicit work on your Mac, with gates that reject malformed output before it reaches the workspace.

What you get

  • Spend frontier budget on diagnosis

    The local model handles bounded edits, tests, and reports after the graph is frozen.

  • Keep the run on your Mac

    Prompts, patches, retries, and artifacts stay local during execution. There is no remote coordinator loop between waves.

  • Approve a frozen graph first

    One approval binds the plan digest and the Git execution digest. Local agents cannot invent shell commands.

  • Two local agents, one resident model

    The shipped profile runs up to two ready tasks at a time on one MLX checkpoint instead of loading a model per call.

  • Every step leaves evidence

    Plans, patches, test receipts, commits, and the final verdict persist under your artifact directory so a run can be inspected later.

How it works

  1. 01

    Plan

    Your frontier agent returns a dependency graph with path ceilings, interface contracts, gates, and acceptance rules.

  2. 02

    Approve

    You inspect the graph, then bind the plan digest and the execution digest. Supervised and YOLO stay operator owned.

  3. 03

    Execute, then review

    Local agents work inside the frozen contract. The frontier agent reviews one compact evidence packet when the session completes.

Questions before you install

Do I need a separate frontier API key for MLX Swarm?

No. Use Claude Code, Codex, or another Agent Skills host you already have. The runtime does not ask for a second provider key.

What Mac do I need?

Apple silicon. The reference Qwen3.6 35B A3B 4bit profile wants about 19 GB of disk and 32 GB of memory. A 4B to 9B MLX checkpoint can fit 16 GB machines if you lower the capability envelope.

Can the local model invent an architecture?

No. At the shipped exact edit level, the frontier agent keeps diagnosis and design. Each mutating task names one file, one symbol, and one mechanical transformation.

What happens if I never approve the plan?

Nothing mutates. Local work starts only after you bind the plan digest and the displayed execution digest in the cockpit or CLI.

Does YOLO merge into my main branch?

No. Isolated worktrees stay isolated. Main checkout YOLO is allowed only on a completely clean repository after you approve that target.

Where do prompts and patches live during a run?

On your machine. Only the planning prompt and the compact final review packet leave when you copy them to a frontier host.

How is this different from an autonomous shell agent?

Agents never provide executable shell commands. Tests come from operator configured argument arrays. Path ceilings, gates, and Git apply checks reject work that steps outside the frozen contract.

What is the license, and what is the risk?

MIT. No account. Cancel is not a concept because nothing is billed. The software is alpha, so expect sharp edges and read the current scope notes in the README.

Install on your Mac

Clone the repo, install the package, then open the cockpit. MIT licensed. No account. Stop whenever you want by closing the process. 

git clone https://github.com/fbzz/mlx-swarm.git
cd mlx-swarm
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
mlx-swarm --config examples/swarm.json ui
